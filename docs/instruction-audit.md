# Instruction audit

Reviewed 2026-09-12 against OpenAI's
[Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra).
The guide favors narrow triggers, conditional reference reads, proportional
verification and completion boundaries that preserve the user's intent.

Scope: Sunclub's tracked `AGENTS.md`, its linked operational instructions, the
session skill catalog and implicated installed skill files. Sunclub had no tracked
`SKILL.md`; the personal `~/.codex/AGENTS.md` was empty. Plugin sources were inspected
as audit evidence, not adopted as instructions for performing this audit.

Repository fixes are applied directly below. Installed-skill fixes are applied by
the short **Task scope and skills** section in `AGENTS.md`, plus **Verify**, rather
than copying or editing vendor caches. These overrides affect work in Sunclub;
they do not change global skill metadata, remove catalog context overhead, or
change personal behavior in other repositories. Personal and plugin files remain
unchanged. The findings below are quoted historical evidence, not live directives.

## Boundaries retained

- Persistence identity, immutable versioned schemas, prior-store migration tests,
  local/CloudKit history preservation and both recovery paths.
- Accessibility, automation permission gates, legacy routes, target/signing IDs
  and existing visual direction.
- Required GitHub `CI`, exact-SHA full CI for refactor/release candidates, and
  final IPA entitlements/watch diagnostics. A local rehearsal is not release authority.
- Explicit user selection among design alternatives, actual tool permissions and
  App Review approval of the concrete package. Existing authorization does not
  authorize unrelated publication, external messages or destructive changes.

## Validation

`just ci-lint` passed; SwiftLint reported existing warnings in unchanged app files
and no serious violations. Local Markdown links resolved, and the diff review
preserved the invariants above. The GitHub `CI` gate is required before merging.
No app behavior, tests, CI classifier, release scripts or skill installation
configuration changed. This audit is a reference artifact; agents do not need to
read it before ordinary tasks.
